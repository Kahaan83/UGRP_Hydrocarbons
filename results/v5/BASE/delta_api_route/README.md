# delta_api_route: declared readings (written before any result exists)

## Purpose

Check that the re-routed prediction API (decision D1 to D4 of the v5 API-route plan) reproduces the scoring route that BASE scored, instead of the old shipped API path. This README is committed before any delta result is generated. It declares what will be read and what counts as agreement; it reports no results.

## Baseline

`api_as_shipped` on the T2 flash set: bias -21.66 C, MAE 21.92 C, over 70 groups (`results/v5/BASE/cells_t2_flash.csv`, pooled row, `api_as_shipped`/`designated`). Values were verified against the CSV before writing (bias -21.656749, MAE 21.916079, n_groups 70, n_rows 70). `rows_t2_flash.csv` has 79 rows.

## Declared readings

- **R-API-1.** On all 79 T2 rows, the API's designated flash equals the route's `pred_lfl_overlay`, and `variants['v4_designated']` equals `pred_designated`, both to 1e-6 C (columns of `results/v5/BASE/rows_t2_flash.csv`).
- **R-API-2.** API kinematic viscosity and density equal the route's values on all T2 rows at the 9 BASE temperatures, to 1e-9 relative.
- **R-API-3.** Flash, heat and aromatics are bit-identical across T_K in {233.15, 288.15, 313.15}.
- **R-API-4.** Both D4 v5pool recipes re-predict through `predict()` within 0.01 C for flash, 1e-6 relative for viscosity, and exactly for heat. Density and freezing differences are reported with their cause.

## Out of scope

Grid rebuild; U1 promotions (K1, F1, LFL overlay); distillation.

- R-API-2: the route values were computed directly with `composition_route.refutas_nu_safe` on the mapped fuel (full precision) at the nine BASE nominal temperatures (233.15, 253.15, 273.15, 288.15, 293.15, 313.15, 333.15, 353.15, 373.15 K). ## Task 7 declared rule: extended design pool (written before any extended-pool design is run)

The `v5pool` designs (6 compounds, as D4) are run first through the route adapter (`RouteLibrary`, `build_route_models`, `design_routed`). The extended pool is the `v5pool` plus, for each (subkind, carbon number) bin below, the registry compound with the lowest InChIKey that satisfies all three `predict_route.predicates` at once: `HAS_GRID`, `HAS_FLASH`, `HAS_SLE`.

| Subkind | nC |
|---|---|
| n_paraffin | 13 |
| n_paraffin | 14 |
| cyclo_mono | 9 |
| cyclo_mono | 10 |
| indan_tetralin | 10 |
| aromatic_di | 11 |

A bin with no qualifying compound is recorded and skipped; it is not filled from a neighbouring bin and no representative is used. A bin whose compound already belongs to the `v5pool` adds nothing. The pool size is therefore whatever the rule yields and may be below 12. Both specs (`astm:jet_a`, `bis:jet_a1`) are run on it with 30 starts and seed 42, and once more with 8 starts for the sensitivity check. One further run per spec on the `v5pool` uses a declared 4 K freezing guard band (freezing limit tightened by 4 K in the optimiser only; the engine's status is unchanged), labelled "indicative guard band, not certified". Freezing stays uncertified: 8 systems support at most an 88.9 % level, and lowering alpha after the failure would be post hoc.

Smoke point is 27.6 mm in every design because the optimiser finds aromatic-free blends; it is outside the model's trusted range, which is why that constraint is uncertified rather than failing.

**Differences to D4.** The `v5pool` recipes are not the D4 recipes (maximum component difference 0.24 for Jet A, 0.51 for Jet A-1; butylcyclohexane up, decalin and decane down). This is expected: the route models use mole-fraction ideal SLE for freezing (the forward model), whereas D4 used mass-fraction SLE in the optimiser. Both are B designs.

**n_starts sensitivity (extended pool, 8 vs 30 starts, seed 42).** The recipes, predictions and categories are identical to the printed digits for both specs. Convergence: 5 of 8 and 16-17 of 30 starts. The 8-start runs took 131 s and 121 s against 505 s and 586 s for 30 starts. Runtimes are wall-clock with up to three runs sharing the machine, so they overstate a single run; relative timing is indicative only.

**Reading.** The route-adapter inverse design finds blends that meet every limit at the point estimate, re-predicts them identically through `predict()`, and names what blocks certification (D8). It does not certify any design. Pools beyond 8 components could not be built on the declared rule because SLE data is missing for most naphthenic and indan/tetralin registry compounds.
