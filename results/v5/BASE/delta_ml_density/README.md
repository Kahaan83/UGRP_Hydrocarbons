# delta_ml_density: learned pair excess-volume correction on ideal volume mixing (declared BEFORE any fit or score)

Requirement source: user ("Yes build density and cetane number"), same pattern as `delta_ml_viscosity`. Real ML, honestly validated.
Nothing is designated or certified unless the readings below pass and the user decides.

## Why
Density is the baseline `dens_idvol` (ideal volume mixing, rho = 1/sum(w_i/rho_i(T))). It neglects excess molar volume, which is the
dominant error (v4 lab: MAE about 1.3 kg/m3 dev, 1.2 locked). The lab density table (10,900 ThermoML rows, 208 systems) is large enough to
learn a pair excess-volume (Redlich-Kister style) correction.

## Model
V_ML = V_ideal + sum_{i<j} x_i x_j g(d_i, d_j, T), rho_ML = (sum_i x_i M_i) / V_ML, x = mole fractions, V in cm3/mol of mixture.
V_ideal = sum x_i M_i / rho_i(T) (identical to the ideal-volume density). g = LightGBM on pair-symmetric features; no composition inside g,
so the correction is zero for a pure component, permutation invariant and defined for any n components. Target: g = VE/(x_i x_j) for binaries,
VE = sum x M / rho_meas - V_ideal (cm3/mol), VE winsorised at +/-2 cm3/mol before division (declared). Sample weight (x_i x_j)^2, normalised to
sum 1 per system.

## Data (all read-only)
- Rows: `results/v4/L/density_lab_residuals.csv` (10,900 rows, 208 systems: 167 dev / 41 locked via its `split_role`, used as is, never re-split;
  626 ternary rows). It has no compositions, so rows are regenerated by `scripts/v4/eval_lab_known_composition.py` functions
  (`prepare_density_records`, tier-1 `PureDensity`, same order) keeping InChIKeys, w, x and rho_i. Positional agreement with the committed
  predicted / measured is asserted to 1e-6; the script stops if it fails.
- Descriptors are computed from the InChI with RDKit (n_carbon, MW, rings, aromatic rings, CH3 count, quaternary C count, molar volume M/rho_i(T)),
  structural class (aromatic / alkene_alkyne / cycloalkane / n_paraffin / iso_paraffin) from the structure, so no registry dependency. At
  inference rho_i comes from the frozen pure grid (read-only, sha-checked); in training from the tier-1 fit that defines the baseline.

## Split and fit
- Train: binary dev rows with x_i x_j >= 0.01 (smaller rows scored, never trained on). Ternaries never trained on.
- Dev estimate: GroupKFold(5) on dev system_id, out-of-fold; dev ternaries scored by their held-out fold's model.
- Test: the 41 locked systems, scored ONCE by the model fitted on all dev training rows, after this README is committed.
  Disclosure: ideal mixing was already scored on the locked 41 in v4; no fitted model was. A locked ternary may contain a dev binary pair (intended).
- Hyperparameters (fixed, no tuning): n_estimators=400, learning_rate=0.05, num_leaves=15, min_child_samples=40, subsample=0.8,
  subsample_freq=1, colsample_bytree=0.8, reg_lambda=1.0, seed=42, deterministic, force_row_wise, n_jobs=1.
- Features: pair-symmetric mean and |difference| of each descriptor, unordered class pair (categorical), T.
- Baselines reported: ideal mixing (the gate), one global constant g, class-pair mean table.

## Metric
System-macro MAE of |rho error| in kg/m3 (mean over a system's rows, then over systems). Intervals: paired system bootstrap, 2000 resamples,
seed 42, 95 % percentile of (MAE_ideal - MAE_ML).

## Declared readings
- R-MLD-1 (dev out-of-fold): system-macro MAE_ML < MAE_ideal and the gain interval is above 0.
- R-MLD-2 (locked 41 systems, one run): same rule, and at most 25 % of locked systems worse by > 0.2 kg/m3 (system MAE_ML - MAE_ideal > 0.2).
- R-MLD-3 (ternaries): MAE_ML <= MAE_ideal on all ternary rows (dev out-of-fold plus locked with the final model), row MAE.
- R-MLD-4 (margin): conformal two-sided margin on the absolute residual in kg/m3, alpha 0.10, group system_id, via `fuelblend.uq.conformal.two_sided_margin`,
  computed on the locked systems' ML residuals as asked; also reported from dev out-of-fold with locked coverage counts. Ideal mixing margin alongside.
- R-MLD-5 (descriptive): endpoint residual share in dev (rows with x_i x_j < 0.01), reported before the locked run; real-fuel / thermoml2020 transfer
  only if quick, else "not run, time".

## Adoption rule (declared)
R-MLD-1 and R-MLD-2 pass -> ships as a labelled variant `ml_pair_excess_volume` with the R-MLD-4 margin, in domain only (every component hydrocarbon
with grid data, every class pair >= 5 training systems, known composition). Designated stays `dens_idvol`; promotion is a user decision, offered
only if R-MLD-3 passes too. If a gate fails, the module and results stay as a scored negative and nothing is exposed.

## Leakage traps (known before fitting)
Target uses the tier-1 ideal volume, not the grid; endpoint rows cannot be represented by x_i x_j g; same system appears at many T (group folds);
no tuning after seeing locked results.
