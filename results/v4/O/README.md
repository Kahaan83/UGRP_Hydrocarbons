# Octane refit on real blends (v4 Task 15)

Generated by `scripts/v4/eval_octane_v4.py`; every number below is read back from `octane_eval_v4.csv`.

## Scope and honest caveats

* Targets are **Co-Optima bRON blends only** (a base gasoline lump of measured RON/MON blended with one pure blendstock at a measured volume fraction). Ruling R17: base RON/MON enter as model **inputs**; the per-property flags `target_ok_ron` / `target_ok_mon` are used (not the OR column `target_ok`). FACE rows (144) are never targets (no fractions in the raw files) and are not evaluated.
* Ruling R19: groups are blendstock CAS numbers, so every CV fold and the locked set test **unseen blendstocks**; the stored dev folds in `splits/v4/real_fuels_v4_splits.json` are reused. Hyper-parameters (Ghosh ridge alpha, GBM size) are selected by grouped CV inside each training fold (R6); locked rows are never used for selection.
* Only two distinct base gasolines exist (RON 90.3 / 87.7). Base-fuel inputs therefore carry almost no information; all variation across blendstocks must be explained by blendstock descriptors (lump class, MW, density, O mass fraction, unsaturation, ring, aromatic) from 18 dev blendstock groups (16 pure + 2 named mixtures). The blendstock's own bRON cannot be an input (it is the target).
* The locked set is thin: 12 RON / 12 MON blends from 4 CAS groups (ethyl butanoate, ethyl acetate, 2-pentanol, ethanol). No confidence statements are made from it.
* The linear-by-mole model assumes a base gasoline of M = 100 g/mol, rho = 745 kg/m3 (typed typical values, not measured) and needs blendstock MW and density, so it is NaN for the two named mixtures (ketone, furan). Per-model N is shown; `*_common` columns restrict to rows every model predicts.
* Lump priors for alcohol/ester/ketone/other oxygenate are the repo's `tail` lump (82/78) because the repo has no literature prior for them; they are learned (ridge-shrunk) by the Ghosh fit path.
