# Task 13 predeclaration: CPU tree models with reproduction gate, curves and nested Optuna

Models: viscosity_pair, density_pair, fusion_estimate, ysi_lgbm, freezing_step3, mixture_gbr (one section each below, committed before that model is run). Dev rows only; locked sets are never scored (the v5 and v6 scripts' own locked stages are not called).
Step 1, reproduction gate: refit with the original parameters on the same rows and folds as the script that produced the number in BASE or v6, and require the dev out-of-fold metric to match the number read from that file to 1e-6 relative. If it fails, the model stops and the reason is reported; step 2 is not run.
Step 2: the same model through `lgb.train` with curve logging under nested Optuna (`configs/v7/search_spaces.yaml: lgbm`: n_estimators 5000, early stopping 100; outer folds identical to the original, inner GroupKFold(3) on the training groups, MedianPruner warmup 20), 60 trials per outer fold, `timeout_s` 1800. Early stopping in the final fit uses a 15 % group-held-out split of the training rows. Objective: weighted validation L2 on the original training target.
Metric and comparison: the original script's dev out-of-fold metric, paired group bootstrap (4000 draws) 90 % CI of the gain (refit-original minus v7), groups as in the original. Gains are tuned on dev rows and are exploratory; nothing is adopted into `predict_fuel()` (a separate user decision).
Guard: the driver hashes `src/` and `results/v5/BASE/` before and after each run and asserts no change. Outputs per model: `repro_gate.json`, `summary.csv`, `curves.csv`, `curves.png`, `best_params.json`.
Reading rule: "v7 improves on the v5 model" only if the 90 % interval of the gain excludes 0 with positive gain; otherwise no evidence of improvement. One comparison per model, no multiplicity correction across models (stated, not hidden).

## viscosity_pair
Original: `scripts/v5/base/delta_ml_viscosity.py` functions (regenerate_rows, build_pairs, train_set, targets, fit_lgb) imported by path; the v4 leaderboard helper it loads from the removed `scripts/v3` is read from a git-recovered copy in `scratch/legacy` (no repo file changed). Rows: 15,827 refutas rows, dev systems (264), GroupKFold(5) on dev system_id. Gate number: `results/v5/BASE/delta_ml_viscosity/readings_dev.json` R-MLV-1 ml mae_b (macro per-system MAE of ln viscosity, warm dev rows). Training pairs: binary rows with x1 x2 >= 0.01, target clip(r, ±0.5)/(x1 x2), weight (x1 x2)^2 normalised per system; v7 prediction of a row is the sum over its pairs of x1 x2 g. Metric for the gain: per-system macro MAE on warm dev rows, systems as groups.

## density_pair
Original: `scripts/v5/base/delta_ml_density.py` functions (regenerate, build_pairs, train_set, targets, fit_lgb) imported by path. Rows: lab mixture density rows (10,900 rows, 208 systems), dev systems (167), GroupKFold(5) on dev system_id. Gate number: `results/v5/BASE/delta_ml_density/readings_dev.json` R-MLD-1 ml mae_b (macro per-system MAE of density in kg/m3, all dev rows). Training pairs: binary rows with x1 x2 >= 0.01, target clip(excess volume, ±2)/(x1 x2), weight (x1 x2)^2 normalised per system; the row density is mm / (v_ideal + sum x1 x2 g) x 1000. Gain metric: per-system macro MAE, systems as groups.

## ysi_lgbm
Original: the LightGBM comparator in `scripts/v5/base/delta_ml_ysi.py` (`lgbm_fit_predict`, weights `ysi_model.weights`, GroupKFold(5) on scaffold group). The shipped YSI model is the ridge; this is the tree comparator, so the question is only whether tuned trees change that comparison. Gate number: `results/v5/BASE/delta_ml_ysi/readings.json` R-MLY-1 mae.lgbm, reproduced over all 222 v5 compounds (a refit of a published number, no tuning, not used for any v7 claim). 53 of the 222 compounds are in the `ysi_holdout` lock, so the v7 comparison uses the 169 dev compounds only, with its own GroupKFold(5) on scaffold group; the refit-original and the v7 model are both scored on those folds. In `summary.csv` the column `mae_physics_baseline` is the training-fold mean (constant) for this model. Gain groups: scaffold groups (21).

## fusion_estimate
Original: the Tm LightGBM in `src/fuelblend/thermo/fusion_estimate.py` as used by `scripts/v5/base/delta_ws3_fusion.py` (`FE.oof_predict`, leave-one-family-out; `FE.LGB_PARAMS`). Only the Tm model is tuned; the dS_fus model is not part of this retrain. Gate numbers: `results/v5/BASE/delta_ws3_pure_gaps/readings_fusion.json`, R-W3-5 `mae_tm_lofo_all_K` (all hydrocarbons) and R-W3-3 `mae_tm_lofo_K` (C8 to C20), both required to 1e-6. Finding before the run: today's `measured_table()` has 119 rows against the 109 that produced BASE (10 compounds were added to the measured sources, and Tm differs by up to 0.26 K), so the unpinned gate fails (53.63 vs 54.69 K all, 50.00 vs 47.75 K C8 to C20). The rows are therefore pinned to the compounds in `results/v5/BASE/delta_ws3_pure_gaps/fusion_oof.csv` (read only); with those rows the gate passes exactly. Outer folds: the 9 families (leave-one-family-out); inner GroupKFold(3) over the training families. Gain groups: families. The primary metric is all-hydrocarbon LOFO Tm MAE; the C8 to C20 gain is also reported (the R-W3-3 scope). The physics comparator column holds the Joback Tm.

## freezing_step3
Original: v6 Track A step 3 monotone LightGBM residual on the isomer-tile base (`scripts/v6/freezing/step3_models.py`: `make_lgbm("pred_e")`, `logo`, `LGB_COLS`, `LGB_MONO`). Rows: the 52 dev rows of `results/v6/freezing/features_preds.csv`; target = freezing_C minus the clipped (-100, -20) `pred_e`; outer folds = leave-one-out (each row its own fold, as the original), inner GroupKFold(3) on entity. Gate: per-row match to `dev_oof_predictions.csv` column `f_lgbm_residual_on_e_isomer_tiles` and MAE 3.3147 from `dev_logo_summary.csv`; those files store 4 decimals, so the gate tolerance is 1e-4 absolute per row and 5e-5 on the MAE instead of 1e-6 relative (stated deviation). v7 keeps the monotone constraints. Gain groups: entities (52). Reported also without fuel 64. The v6 freezing verdict (no skill on real fuels) is not reopened: these are already-seen dev rows, exploratory.
