| metric | report | rerun |
|---|---|---|
| viscosity −20 °C log-RMSE, physics | 0.3189 | 0.3191 ✓ |
| viscosity −20 °C log-RMSE, DeepSets | 0.1633 | **0.2720** ✗ |
| viscosity −20 °C log-RMSE, Pairwise | 0.1795 | **0.3400** ✗ |
| viscosity −40 °C log-RMSE, DeepSets / Pairwise | 0.4968 / 0.5012 | **0.6310 / 0.6870** ✗ |
| viscosity +20 °C log-RMSE, DeepSets / Pairwise | 0.1172 / 0.1082 | **0.1302 / 0.1447** ✗ |
| density 15 °C RMSE, physics | 9.73 (bias +0.51) | 9.728 (bias +0.49) ✓ |
| density 15 °C RMSE/bias, DeepSets | 10.30 (+3.64) | **9.747 (−0.23)** ✗ (bias sign flip) |
| density 15 °C RMSE/bias, Pairwise | 9.85 (+1.22) | 9.920 (+1.59) — RMSE pass, **bias off by 0.37** |

Crucially, the committed `hindcast_predictions.csv` reproduces from the current bundles; so the discrepancy is
**not** a reproducibility failure of the script — it is a **stale/inconsistent report**: §3.2 was written from a
different (better) set of DeepSets/Pairwise bundles (or a different aggregation over the MC draws) than the ones
frozen under `results/pairwise/*.pt` with this CSV. Consequence: the headline claim "error cut in half at −20 °C
(0.3189 → 0.1633)" is **not supported by the frozen artifacts**; the frozen artifacts give 0.3189 → 0.2720
(−15 %, not −49 %). Any downstream text or paper draft must be corrected or the bundles re-frozen.

Also flagged (not a report metric): the `*_mc_spread` columns differ systematically (mean 3.59 → 3.95), i.e. the
stored run used a different `--mc` draw sequence; predictions themselves are unaffected.
